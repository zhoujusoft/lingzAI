# 🚀 lingzAI V1.3.3 升级发布：从“企业 Agent 基座”到“企业 Agent 生产线”

> 如果说 V1.2.0 让 lingzAI 完成了从“单纯聊天”到“企业 Agent 基座”的跨越，那么 V1.3.3 做的事情，就是把这个基座继续往前推了一步：  
> **让 Agent 不只会问答，还能被创建、被发布、被接入、被执行、被交付。**

这次升级不是简单补几个按钮，而是围绕企业真实落地场景，把 Agent 的全生命周期继续补齐：

- 🧩 能不能快速创建一个业务技能？
- 🌐 能不能把技能发布成一个独立 Chatbot？
- 💬 能不能接入微信、企业微信、Webhook 等外部渠道？
- 📎 能不能处理用户上传的附件？
- ⚙️ 能不能执行脚本、生成文件、输出可下载结果？
- 🧠 能不能接入私有模型和 vLLM？

V1.3.3 的答案是：可以，而且已经开始形成完整闭环。

---

## ✨ 本次升级亮点

### 🏭 1. 新增「技能工坊」：让企业自己生产 Agent

V1.3.3 新增后台「技能工坊」模块，开始把技能从“开发者写好的能力”升级为“可在线创建、迭代、管理的项目”。

你可以把它理解为 lingzAI 的 Agent 工作台：

- 支持创建和管理技能项目
- 支持维护技能名称、描述、分类、图标、草稿技能名、运行时技能名
- 支持查看技能项目文件树和文件内容
- 支持围绕单个技能项目持续对话式修改
- 支持保留项目会话、消息记录和最近编辑上下文

这意味着企业后续可以围绕“业务场景”持续打磨自己的 Agent，而不是每次都从代码层重新开始。

---

### 🌐 2. 技能可发布为独立 Chatbot：从后台能力到前台应用

V1.2.0 已经具备技能目录和技能对话能力，V1.3.3 则进一步补上了“发布态”。

现在，一个技能可以被发布为独立 Chatbot 应用，形成对外访问入口：

- 支持发布应用编码、名称、描述和发布状态
- 支持独立的 Chatbot 访问入口
- 支持免登录访问校验
- 支持发布态技能的会话列表、消息历史、会话重命名、会话删除
- 支持按 appCode 访问指定技能应用

简单说：  
**技能不再只是后台里的一个能力，而是可以变成一个真正可交付、可访问、可运营的 Agent 应用。**

---

### 📡 3. 新增「渠道接入」：Agent 走出平台，进入业务现场

V1.3.3 新增渠道接入能力，让 Agent 不再只停留在平台页面里。

本次新增：

- 渠道配置管理
- 渠道启动、停止、重启
- 外部会话与内部会话绑定
- 外部消息路由到通用聊天、技能聊天、数据集问答
- Webhook 渠道基础能力
- 微信 iLink 渠道基础能力
- 企业微信渠道基础能力
- 渠道用户绑定和独立登录态管理

这让 lingzAI 开始具备“多入口服务能力”：  
用户可以在企业微信里问，在微信里聊，也可以通过 Webhook 接入业务系统。

Agent 开始真正靠近业务现场。

---

### 🧠 4. 会话内核升级：从聊天记录到 Agent 事件流

V1.3.3 对会话底层做了关键升级。

过去的会话更像“问题和回答”的记录；现在的会话开始升级为：

- 会话主表
- 消息主表
- 事件流表
- 模型上下文消息表

这为后续更复杂的 Agent 行为打下基础，比如：

- 工具调用过程记录
- 运行时执行过程记录
- 文件产物生成记录
- 多步骤任务状态追踪
- 更稳定的长上下文管理

换句话说，lingzAI 的会话模型开始从“聊天系统”向“Agent 执行系统”演进。

---

### ⚙️ 5. 新增 Agent Runtime：Agent 可以读文件、跑脚本、产出结果

V1.3.3 新增统一运行时工具 `runtime_tool`，这是本次升级里非常关键的一块。

它让 Agent 开始具备执行能力：

- 读取文件
- 写入文件
- 查看目录
- 查看文件状态
- 执行 Python 脚本
- 写入最终产物
- 输出可下载文件

同时新增运行时工作区语义：

- `/workspace` 工作目录
- `/uploads` 用户上传附件
- `/outputs` 输出目录
- `/temp` 临时目录
- `/skill` 技能目录

这意味着 Agent 不再只是“生成一段文本”，而是可以完成更真实的工作：

- 分析一个 Excel
- 读取一份 Word
- 调用脚本处理数据
- 生成报告文件
- 输出可下载交付物

这一步，是 lingzAI 从“问答型 Agent”走向“执行型 Agent”的关键升级。

---

### 📎 6. 附件上传与按需解析：让 Agent 真正读懂文件

企业场景里，很多问题都不是一句话能说清楚的，往往要带上文档、表格、制度、合同、模板。

V1.3.3 新增附件处理能力：

- 支持聊天附件上传
- 支持附件进入当前会话上下文
- 支持附件物化到运行时工作区
- 新增 `parse_file` 工具
- 支持按需解析 Word、Excel 等文件内容
- 支持输出正文、Markdown、章节、表格、Sheet、实体摘要等结构化视图

这里的重点是“按需解析”。

系统不会粗暴地把所有文件全文塞给模型，而是在 Agent 真正需要阅读附件时，再触发解析。这样更适合大文件、复杂 Office 文件和多步骤执行型任务。

---

### 🧬 7. 模型运行时增强：更适合私有化和多模型部署

V1.3.3 对模型运行时继续增强，尤其面向私有化部署和企业自有模型服务。

新增和增强能力包括：

- 支持通义在线模型
- 支持 vLLM 私有模型服务
- 支持 CHAT、EMBEDDING、RERANK 多能力类型
- 支持数据库化维护模型定义
- 支持默认模型绑定
- 支持 Base URL、接口路径、模型名、temperature、max tokens、thinking、向量维度、超时等参数配置

对于企业来说，这意味着 lingzAI 可以更自然地适配：

- 云上大模型
- 私有模型
- 本地 vLLM 服务
- 不同能力使用不同模型

模型不再只是写在配置文件里的参数，而是进入平台化治理。

---

### 🛠️ 8. 工具治理增强：技能依赖更清楚，迁移更稳定

随着技能、知识库、数据集、API、MCP 越来越多，工具治理会变得非常重要。

V1.3.3 在这方面做了多项增强：

- 知识库工具新增稳定编码
- 数据集工具新增稳定编码
- 工具发布名称减少 ID 漂移
- 技能目录新增工具绑定状态
- 支持标记依赖缺失、需要重新绑定、不支持等状态
- 支持记录工具绑定异常说明和明细
- 运行时工具与业务工具做类型区分

这让管理员可以更清楚地知道：

- 某个技能依赖哪些工具
- 哪些依赖已经就绪
- 哪些工具需要重新绑定
- 哪些能力迁移后需要人工处理

对于企业环境迁移、私有部署和技能复用，这是非常实用的一步。

---

### 📊 9. 低代码与数据集联动增强：更靠近业务执行

V1.3.3 继续增强低代码、数据集和技能之间的联动能力。

新增低代码菜单编码绑定后，数据集对象、字段和具体业务表单之间可以建立更稳定的关联。

这为下面这类业务链路继续打基础：

1. 用户用自然语言描述需求
2. Agent 查询业务数据
3. Agent 生成表单草稿
4. 用户确认
5. Agent 调用低代码 API 提交

也就是说，Agent 正在从“帮你查”升级为“帮你办”。

---

### 🧪 10. 新增业务技能模板：从平台能力走向业务样板

V1.3.3 新增了更贴近业务落地的技能模板。

#### 🧾 政策适用对象筛选

面向政策服务场景：

- 上传政策文件
- 智能识别政策适用对象范围
- 结合人员数据集筛选符合条件的人群
- 为精准触达、政策服务和名单生成提供支持

#### 📦 订单履约协同助手

面向销售与供应链协同场景：

- 根据客户采购需求理解订单意图
- 联动库存数据集进行校验
- 分步完成订单申请确认
- 分步完成发货申请确认
- 对接订单申请 API、发货申请 API 和库存数据集工具

这些技能模板说明 lingzAI 的能力正在从“通用平台”进入“业务流程样板”。

- 外部渠道接入

- 附件解析
- 文件产物交付
- 私有模型适配
- 工具绑定治理
- 业务技能模板
