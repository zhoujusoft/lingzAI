# 🚀 lingzAI V1.4.2 升级发布：从“Agent 生产线”到“可治理、可运营的企业 Agent 平台”

> 如果说 `V1.3.3` 让 lingzAI 从“企业 Agent 基座”进一步升级为“企业 Agent 生产线”，  
> 那么 `V1.4.2` 做的事情，就是把这条生产线补上真正可长期使用的治理能力。  
> 
> **让 Agent 不只是能创建、能发布、能接入、能执行，  
> 还开始变得能控权、能限额、能切换、能运营、能品牌化。**

这次升级的重点，不再只是继续堆叠功能模块，而是开始围绕企业在真实使用阶段最常遇到的几个问题，补齐平台级能力：

- 用户怎么安全登录、注册和创建？
- 不同角色能看到哪些后台菜单？
- 资源能不能只让创建人看，或者让所有人看但限制操作？
- 对话时能不能自己切模型，而不是永远绑死默认模型？
- Token 用量能不能纳入管理，而不是无限消耗？
- 技能工坊里的工具到底哪些是全局可用，哪些必须手动绑定？
- 平台能不能换成客户自己的系统名称和 Logo？
- 渠道接入能不能真正按用户运行，而不是只有一个“公共登录态”？

`V1.4.2` 的回答是：  
**可以，而且这些能力已经不只是零散补丁，而是在形成企业级 Agent 平台该有的治理骨架。**

---

## ✨ 本次升级亮点

### 🔐 1. 登录安全与用户创建增强：从“能进系统”到“安全、可控地进系统”

`V1.4.2` 首先补强的是用户体系。

在企业环境里，平台要想真正给多人长期使用，登录与账号管理不能只停留在“账号密码可登录”这么简单。

本次新增：

- 登录验证码能力
- 登录页验证码获取与校验流程
- 前台注册页
- 管理员对话式用户创建能力
- 隐藏式 `register-user` 技能
- 专属原生工具：
  - `register_user_preview`
  - `register_user_confirm`

这意味着什么？

以前，管理员创建用户更像一个后台管理动作；  
现在，这件事已经可以被 Agent 化。

管理员可以直接通过对话收集用户名、姓名、密码、联系方式等信息，先生成确认摘要，再决定是否真正创建。  
这让“平台管理”本身也开始被平台里的 Agent 接管一部分。

---

### 🧠 2. 聊天支持手动切换模型：从“系统默认”到“会话自主选择”

`V1.3.3` 已经把模型库、默认模型绑定、私有模型接入这些底座铺好了。  
`V1.4.2` 则继续往前走了一步：

**用户在通用聊天中，已经可以手动切换当前会话所使用的模型。**

本次补齐：

- 通用聊天模型选择器
- 会话级模型绑定
- 历史会话恢复模型展示
- 模型失效后的明确提示
- 运行模型信息的完整统计落库

新增记录能力包括：

- `chat_model_id`
- `model_id`
- `model_name`
- `adapter_type`
- `llm_call_count`

这带来的变化非常关键：

过去我们更多是在“平台层面配置模型”；  
现在开始进入“用户在会话层面选择模型”。

也就是说，lingzAI 不再只是一个“统一模型入口”，而开始具备真正的多模型使用体验。

---

### 💰 3. Token 额度治理上线：让 Agent 平台进入可运营阶段

企业 Agent 平台一旦多人使用，就一定会遇到一个问题：

> 模型调用成本怎么控制？

`V1.4.2` 正式把这件事平台化了。

本次新增：

- 站内用户 Token 额度账户
- 系统级额度开关
- 新用户初始额度配置
- 管理员发放额度
- 管理员修改剩余额度
- 用户不限量模式
- 前台剩余额度展示
- 使用中的自动扣减与结算

并且这次不是只在后台挂一个配置页，而是把额度真正接进了运行链路：

- 通用聊天接入额度校验
- 知识库问答接入额度校验
- 技能工坊创建对话接入额度校验
- 技能工坊试运行接入额度校验

换句话说，平台已经不只是“记录 usage”，而是开始具备：

- 成本约束
- 用户运营
- 额度分配
- 限额执行

这一步非常重要，因为它直接决定一个 Agent 平台能不能从“演示系统”走向“真实运营系统”。

---

### 🧾 4. 角色菜单权限上线：后台终于开始“按人显示”

很多平台到了后期都会遇到一个尴尬的问题：

功能很多，但所有后台菜单几乎都摊给所有人。

`V1.4.2` 开始解决这个问题。

本次新增：

- `sys_role_menu_permission` 角色菜单权限表
- 后台路由按权限过滤
- 侧边栏按权限过滤
- 角色管理中的菜单权限配置
- 菜单权限分组展示

当前权限分组已覆盖：

- 内容与技能
- 接入与模型
- 资源目录
- 系统管理

这意味着 lingzAI 的后台不再是“一个大后台 everyone all in”，而开始具备面向不同岗位的后台可见范围控制。

比如：

- 有的人只需要看知识库和技能工坊
- 有的人只负责渠道与模型
- 有的人只管理数据源、数据集和工具
- 有的人才应该看到用户、角色和系统配置

这让后台开始更像企业系统，而不是纯研发调试控制台。

---

### 🔒 5. 资源权限扩展：从知识库开始，走向企业协作治理

这是 `V1.4.2` 最像“企业级平台升级”的一部分。

`V1.3.3` 已经让知识库、数据集、MCP、工具都接进了平台。  
但真实企业环境里，下一步一定会问：

> 谁可以看？谁可以改？谁可以绑定？谁可以发布？

`V1.4.2` 开始把这个问题结构化。

首先补到知识库：

- 创建人字段
- 权限范围字段
- 三档权限模型
- 发布工具权限同步
- 技能绑定可见性同步

权限范围支持：

- 仅创建人可见可操作
- 所有人可见，仅创建人可操作
- 所有人可见可操作

更重要的是，这套能力没有停在知识库本身，而是继续延展到：

- 数据源
- 数据集
- MCP 服务
- 工具目录项

这意味着平台开始从“资源都能接进来”，继续升级为“资源接进来之后还能被治理”。

对于企业来说，这一步的意义非常实际：

- 业务部门可以沉淀自己的资源
- 平台管理员仍然可以兜底管理
- 不同人之间可以共享，但不一定共享编辑权
- 技能绑定不再默认无边界扩散

平台开始真正具备企业协作里的“边界感”。

---

### 🧰 6. 技能工坊治理继续增强：从“会生成”到“会约束、会隔离”

`V1.3.3` 里，技能工坊已经是一个很重要的新能力。  
到了 `V1.4.2`，我们继续把它往稳定生产方向推。

本次新增和增强：

- 工具库全局可用开关 `enabled_global`
- 技能工坊工具自动绑定
- 项目设置中的工具类型筛选
- 技能工坊接入 Token 限额
- 运行时按 skill name 注入专属原生工具

这里有两个特别关键的变化。

#### 第一，工具开始区分“全局可用”和“按需绑定”

这意味着不是所有工具都要默认灌进所有对话上下文。  
平台终于开始有能力明确区分：

- 哪些工具是公共基础能力
- 哪些工具需要项目级绑定
- 哪些工具只属于某个特定技能

#### 第二，技能专属工具开始被真正隔离

像 `register-user` 这种技能，其内部工具不应该暴露给别的技能去乱用。  
`V1.4.2` 已经补上这层机制。

这让技能工坊不只是“能生成技能”，而是开始有了技能隔离与运行时边界。

---

### 🎨 7. 系统品牌配置上线：平台开始可以“换成客户自己的样子”

企业落地时，一个很现实的问题是：

> 平台能不能不要永远长得像默认产品？

`V1.4.2` 给出了基础答案。

本次新增：

- 系统名称配置
- Logo 配置
- Favicon 配置
- 品牌资源上传
- 登录页、注册页、前后台导航同步展示品牌配置

这意味着 lingzAI 开始具备基础品牌化能力：

- 登录页可以换成客户自己的系统名
- 平台图标可以换成客户自己的 Logo
- 浏览器页签也可以同步品牌识别

虽然这不是“AI 能力”本身，但它决定了一件事：

**这个系统能不能像客户自己的系统一样被使用。**

### 📡 8. 渠道接入继续走深：从“接进来”到“按用户长期运行”

`V1.3.3` 已经把渠道接入打通了基础链路。  
`V1.4.2` 则把渠道能力往真实运行态继续推进。

新增和增强包括：

- 企业微信认证与多账号支持增强
- 微信/企业微信按 `ownerUserId` 隔离运行态
- 登录态保存与恢复
- 登录态失效清理
- 用户级会话绑定
- 输入中状态支持
- 消息去重与重连处理

这背后反映的是一个很大的变化：

过去的渠道更像“平台连了一个外部入口”；  
现在的渠道开始更像“每个用户有自己的渠道运行上下文”。

这会显著提升真实企业场景下的可用性，比如：

- 不同运营人员管理不同渠道账号
- 渠道掉线后可恢复
- 不同用户不会互相串运行态
- 外部消息路由更稳定

Agent 真正从平台页面，继续走进了企业自己的工作入口里。

lingzAI 的演进路线并不是只做一个“通用 Agent 平台”，

- 能够拉近平台与真实业务距离的应用形态

## 🧭 从 V1.3.3 到 V1.4.2，最大的变化是什么？

`V1.3.3` 重点解决的是：

> 企业如何创建、发布、接入和运行 Agent？

所以它补齐了：

- 技能工坊
- 技能发布 Chatbot
- 渠道接入
- 会话事件模型
- Runtime 执行能力
- 附件解析
- 文件产物交付
- 私有模型适配

而 `V1.4.2` 更进一步解决的是：

> 当企业真的开始长期使用这些 Agent，平台如何治理、约束和运营？

所以它补齐了：

- 登录安全与注册入口
- 对话式用户创建
- 会话级模型切换
- Token 额度治理
- 角色菜单权限
- 资源级权限控制
- 工具全局开关与技能专属工具隔离
- 品牌化配置
- 渠道按用户运行态管理

换句话说：

`V1.3.3` 更像是把生产线搭起来；  
`V1.4.2` 则是在给这条生产线加上规则、工位边界、配额系统和运营面板。

它开始不只是一个会工作的 Agent 平台，  
而是一个更适合多人协作、长期落地、真实运营的企业 Agent 平台。
